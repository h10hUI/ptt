# ptt 仕様書

ptt(PTT Time Tracking)は、カレントディレクトリをプロジェクトとして自動でタイムトラッキングを行う、ターミナル常駐型のCLIツール。計測結果はGAS経由でGoogleスプレッドシートに送信する。

- コマンド名：`ptt`
- 実装言語：Deno（TypeScript）
- 対応OS：macOS
- 配布：JSR（`jsr:@h10hui/ptt`）

---

## 1. 基本動作

| 項目 | 内容 |
|---|---|
| 起動 | 任意のディレクトリで `ptt` を実行 |
| サブコマンド | なし |
| 計測開始 | 起動と同時に自動で開始（初回はセットアップ完了後） |
| 操作 | なし（キーバインドなし） |
| 停止後 | 記録を送信してプロセスを終了 |

### 1.1 短時間の記録

- 作業時間（日付分割前の合計）が**1分未満**の記録は送信せず、退避ファイルを削除して終了する

### 1.2 停止時の送信失敗

- 停止時の送信は6.6の手順（リネームして処理権を確保 → 送信）で行う
- 送信は最大3回試行する（1回あたりのタイムアウト10秒、試行間隔2秒）
- 3回とも失敗した場合は `.sending` を `.json` に戻し、次回起動時の再送対象にして終了する

### 1.3 終了コード

| 終了コード | 状況 |
|---|---|
| 0 | 正常停止（シグナル／アイドル／スリープ）。1分未満で記録を捨てた場合も含む |
| 1 | 送信失敗（記録は退避済み）、セットアップ失敗・タイムアウト、clasp／Node.js が見つからない等のエラー |

- 停止理由ごとの区別は行わない

## 2. 初回セットアップ

GASのURLが未保存（`~/.local/share/ptt/config.json` が存在しない）場合、計測の前にセットアップを行う。pttがclaspを実行し、各ステップの完了を自動で検知して進める。ユーザーの操作はブラウザでの操作のみとし、Enterの入力・コマンドの実行・URLの貼り付けは不要とする。

### 2.1 前提

- Node.js 22以上（clasp 3.x の動作要件）
- clasp 3.x（`@google/clasp`）

| 状況 | 検知方法 | 表示内容 |
|---|---|---|
| clasp が見つからない | `clasp --version` の実行時に `Deno.errors.NotFound` | `npm install -g @google/clasp` を表示 |
| clasp は存在するが Node.js がない | 終了コード127、または標準エラーに `node` を含む | Node.js 22以上のインストールが必要な旨を表示 |
| clasp が 3.x 未満 | `clasp --version` の出力から最初の `数字.数字.数字` を正規表現で取り出し、メジャーバージョンが3未満 | `npm install -g @google/clasp@latest` を表示 |
| 権限エラー等その他の失敗 | 上記以外の例外・非0終了 | エラー内容（標準エラー）をそのまま表示 |

- いずれの場合も終了コード1で終了する
- clasp 3.x 専用とし、2.x の旧コマンド名には対応しない（3.x では `create-script` / `create-deployment` / `update-deployment` / `show-authorized-user` を使用）

### 2.2 手順

| # | 処理 | 完了の検知方法 | ユーザーの操作 |
|---|---|---|---|
| 1 | `clasp show-authorized-user --json` でログイン状態を確認し、未ログインなら `clasp login` を実行 | `clasp login` のプロセス終了後、再度 `show-authorized-user` で確認 | ブラウザで認証 |
| 2 | `gas/.clasp.json` が無ければ、`~/.local/share/ptt/gas/` で `clasp create-script --type standalone --title "ptt"` を実行 | 成功（`.clasp.json` が作成される）するまで5秒ごとに再試行。「Apps Script APIが無効」のエラーが返った場合は有効化用のURL（`https://script.google.com/home/usersettings`）を表示 | （APIが無効の場合のみ）URLを開いてスイッチをオン |
| 3 | `Code.js` / `appsscript.json` を書き出し、`clasp push --force` を実行。続けて、`gas/deployment.json` にデプロイIDが無ければ `clasp create-deployment --json`、あれば `clasp update-deployment <デプロイID>` を実行し、デプロイIDを `gas/deployment.json` に保存 | 各コマンドの終了 | なし |
| 4 | WebアプリのURL（`https://script.google.com/macros/s/<デプロイID>/exec`）を表示し、3秒ごとにGETでアクセス | レスポンス本文が3.2のJSONとして解釈でき、`status` が `ptt ok` | URLを開いてアクセスを許可 |
| 5 | WebアプリのURLとスプレッドシートのURLを `config.json` に保存し、スプレッドシートのURLを表示して計測を開始 | — | なし |

- 手順1の判定：`show-authorized-user --json` の終了コードと出力で判定する。未ログイン時の出力形式は実装時に実際の出力で確認する
- 手順2の再試行：再試行の前に `gas/.clasp.json` の有無を確認し、存在すれば作成済みとみなして次へ進む（通信エラー等で作成だけ成功していた場合の重複作成を防ぐ）
- 手順3のデプロイID取得：グローバルオプション `--json` の出力からデプロイIDを取り出す。取り出せない場合は、テキスト出力から `AKfyc` で始まるID（正規表現 `AKfyc[\w-]+`）を取り出す。実際の出力形式は実装時に確認する
- 手順4の承認判定：HTTPステータスコードでは判定しない（承認前のエラーページもステータス200で返る場合があるため）。本文がJSONとして解釈できないものはすべて「未承認」とみなす
- 表示上は手順1〜4を `[1/4]`〜`[4/4]` とし、手順5は番号を付けずに完了メッセージとして表示する
- ファイルの書き出し（手順3）を `create-script`（手順2）の後に行うのは、`create-script` がGAS側の初期ファイルをローカルにダウンロードする際に、書き出し済みのファイルを上書きする可能性があるため
- `--type sheets` ではなく `--type standalone` で作成するのは、APIが無効のときに「スプレッドシートだけ作成されてGASプロジェクトの作成に失敗する」ことを防ぎ、安全に再試行できるようにするため（スプレッドシートはGAS側で作成する）

### 2.3 待機とタイムアウト

| 待機 | ポーリング間隔 | タイムアウト |
|---|---|---|
| Apps Script APIの有効化待ち（手順2） | 5秒 | 10分 |
| アクセス承認待ち（手順4） | 3秒 | 10分 |

- タイムアウトはステップごとに計測する
- タイムアウトした場合は、再度 `ptt` を実行すれば続きから再開できる旨を表示し、終了コード1で終了する

### 2.4 中断時の再開

セットアップの各手順は、以下の状態から実行要否を判定する。

| 手順 | 判定 | 再実行時の動作 |
|---|---|---|
| 1 ログイン | 毎回 `show-authorized-user` で確認 | ログイン済みなら即座に次へ |
| 2 プロジェクト作成 | `gas/.clasp.json` の有無 | あればスキップ |
| 3 アップロード | 毎回実行 | 常に最新のコードで上書き |
| 3 デプロイ | `gas/deployment.json` の有無 | あれば `update-deployment`（URLは変わらない）、無ければ `create-deployment` |
| 4 承認確認 | 毎回GETで確認 | 承認済みなら即座に次へ |
| 5 保存 | `config.json` の有無 | あればセットアップ自体を行わない |

### 2.6 再セットアップ

- サブコマンドがないため、再セットアップする場合は `~/.local/share/ptt/config.json` を削除して再起動する
- `gas/` が残っている場合は、既存のGASプロジェクトに再デプロイし、同じスプレッドシートに書き込みを続ける（2.4の判定による）
- GASプロジェクトとスプレッドシートを作り直したい場合は、`gas/` も削除する（古いGASとスプレッドシートはGoogle側に残る）
- `gas/Code.js` / `gas/appsscript.json` は毎回pttが上書きする。GAS側のコードはpttが管理するものとし、ユーザーによる編集は想定しない

## 3. GAS側の仕様

ファイルの内容は、pttのソース内に文字列リテラルとして持つ（例：`src/gas_files.ts`）。JSRからインストールした場合、`import.meta.url` からの相対パスでテキストファイルを読み込めないため。セットアップ時に `~/.local/share/ptt/gas/` に書き出す（ディレクトリが無い場合はpttが作成する）。

### 3.1 `appsscript.json`

```json
{
  "timeZone": "<セットアップ時の端末のタイムゾーン>",
  "runtimeVersion": "V8",
  "webapp": {
    "access": "ANYONE_ANONYMOUS",
    "executeAs": "USER_DEPLOYING"
  }
}
```

- `timeZone` には、書き出し時に `Intl.DateTimeFormat().resolvedOptions().timeZone` の値（例：`Asia/Tokyo`）を入れる
- `access` は必ず `ANYONE_ANONYMOUS` にする（`ANYONE` は「Googleアカウントにログイン済みのユーザー」を意味し、pttからのリクエストを受け付けない）

### 3.2 `Code.js`

| 関数 | 動作 |
|---|---|
| `doGet` | スプレッドシートを（無ければ作成して）取得し、`{"status": "ptt ok", "spreadsheetUrl": "<URL>"}` をJSONで返す |
| `doPost` | 受け取ったレコードをスプレッドシートに追記し、結果をJSONで返す |

#### スプレッドシートの作成

- スプレッドシートの取得・作成は `doGet` / `doPost` 共通の関数で行い、`LockService.getScriptLock()` で排他制御する（同時実行時の二重作成を防ぐ）
- スプレッドシートIDはスクリプトプロパティに保存し、2回目以降はそのIDで開く
- 作成時の設定：
  - タイトル：`ptt`
  - タイムゾーン：スクリプトのタイムゾーン（`Session.getScriptTimeZone()`）
  - 1行目に見出し（プロジェクト名 / 開始日時 / 終了日時 / 作業時間）
  - A列（プロジェクト名）の書式を書式なしテキスト（`@`）にする（`=` 等で始まる名前が数式として解釈されるのを防ぐ）
  - B・C列の表示形式を `yyyy-mm-dd hh:mm:ss`、D列を `[h]:mm:ss` にする

#### `doPost` のリクエスト

- 本文はJSON（Content-Type は `text/plain`。GAS側では `e.postData.contents` を `JSON.parse` する）
- 日付分割した複数レコードは1リクエストにまとめて送る

```json
{
  "records": [
    {
      "project": "ptt",
      "start": "2026-10-30 23:00:00",
      "end": "2026-10-31 00:00:00",
      "durationSec": 3600
    },
    {
      "project": "ptt",
      "start": "2026-10-31 00:00:00",
      "end": "2026-10-31 01:30:00",
      "durationSec": 5400
    }
  ]
}
```

#### `doPost` の書き込み

- `start` / `end` はスクリプトのタイムゾーンの日時として `Date` に変換して書き込む
- `durationSec` は日数換算の数値（`durationSec / 86400`）として書き込み、`[h]:mm:ss` 形式で表示する（スプレッドシート上で合計などの計算ができるようにするため）
- 全レコードを一括で追記する

#### `doPost` のレスポンス

| 状況 | レスポンス |
|---|---|
| 成功 | `{"ok": true, "count": <追記した行数>}` |
| 失敗 | `{"ok": false, "error": "<エラー内容>"}` |

## 4. プロジェクトの識別

| 項目 | 内容 |
|---|---|
| 識別キー | 起動時のカレントディレクトリの**名前**（パスではない） |
| Git | 関係しない |
| 親子関係 | 関係しない（各ディレクトリを独立したプロジェクトとして扱う） |
| プロジェクト名 | ディレクトリ名を自動で使用 |
| 同名ディレクトリ | 別パスでも同一プロジェクトとして集計する |

### 4.1 プロジェクト名の正規化

- 制御文字（`U+0000`〜`U+001F`、`U+007F`〜`U+009F`。改行・タブを含む）を除去する（端末表示への制御シーケンスの混入と、セル内改行を防ぐ）
- 除去後に空文字になった場合、およびルートディレクトリ（`/`）の場合は `/` とする
- 数式インジェクションはGAS側（A列の書式なしテキスト化）で防ぐため、ptt側では記号の変換を行わない

## 5. 計測

### 5.1 複数起動

- WezTermの複数ペインなど、`ptt` を実行したペインごとに独立して計測する
- 同一プロジェクトを複数ペインで同時に計測した場合の二重計上は許可する

### 5.2 停止条件

| 条件 | 検知方法 | 記録上の終了時刻 |
|---|---|---|
| ターミナルのセッション終了 | `SIGHUP` を受信（`SIGINT` / `SIGTERM` も同様に扱う） | 受信時刻 |
| アイドル（30分） | 30秒ごとにmacOS全体の無操作時間（`ioreg -c IOHIDSystem` の `HIDIdleTime`）を取得し、30分以上で停止 | 検知時刻 − 実際の無操作時間（＝最後に操作した時刻） |
| スリープ | 1秒ごとに時刻を確認し、前回の確認から60秒以上空いていた場合にスリープとみなす | スリープ前の最後の確認時刻 |

- ディレクトリ移動は停止条件に含めない
- 一時停止（pause）機能はなし
- スリープ検知はシグナル・IOKit通知（FFI）を使わず、時刻の飛びで判定する（実装の簡素化と、`--allow-ffi` を避けるため）

### 5.3 計測ループ

- 1秒ごとのループを1本だけ持ち、各回で以下の順に処理する
  1. 時刻の確認とスリープ判定（前回から60秒以上空いていれば停止処理へ）
  2. 経過時間の表示更新
  3. 10回に1回（10秒ごと）、退避ファイルの最終生存時刻を更新
  4. 30回に1回（30秒ごと）、`ioreg` を非同期で実行してアイドル判定
- スリープ判定をアイドル判定より先に行うことで、復帰直後にスリープ時間をアイドルと誤判定しないようにする
- `ioreg` は30秒ごとにのみ実行し、1秒ごとの処理は時刻の比較だけにする

### 5.4 アイドル時間の取得

- `ioreg -c IOHIDSystem` の出力から正規表現 `"HIDIdleTime" = (\d+)` で最初の値を取り出す
- 値の単位は**ナノ秒**。ミリ秒に変換（÷1,000,000）して使う
- `ioreg` の出力書式に依存するため、取得・解析に失敗した回はアイドル判定をスキップし、計測を継続する（エラー表示もしない）

### 5.5 停止処理

停止理由にかかわらず、以下の共通の経路で処理する。

1. 終了時刻を確定し、退避ファイルに同期的に書き込む
2. 1分未満なら退避ファイルを削除して終了（1.1）
3. 6.6の手順で送信（1.2）
4. 停止理由と記録内容を表示して終了

- 表示は書き込み・送信の後に行い、表示のエラー（ターミナルを閉じて出力先が無い場合など）は無視する
- 表示内容の例：
  - アイドル：`30分操作がなかったため停止しました（1:12:30を記録）`
  - スリープ：`スリープを検知したため停止しました（0:45:10を記録）`
  - シグナル：`停止しました（2:03:44を記録）`
  - 1分未満：`1分未満のため記録しませんでした`
  - 送信失敗：`送信に失敗しました。次回起動時に再送します`

### 5.6 表示

- 経過時間を `H:mm:ss` 形式で1秒ごとに更新する
- 同じ行を書き換える（`@cliffy/ansi` で行頭へのカーソル移動と行の消去を行う）
- 標準出力が端末でない場合（`Deno.stdout.isTerminal()` が `false`。リダイレクト・パイプ時）は、ライブ表示と停止時の表示を行わず、計測と送信のみ行う
- ToDoの表示は別途検討（本仕様の範囲外）

## 6. データ送信

### 6.1 送信先

- セットアップで作成したGASのWebアプリにPOSTする（形式は3.2）
- GASのWebアプリはPOST後に `script.googleusercontent.com` へリダイレクトされる。Deno の `fetch` はリダイレクトを自動で追従し、POSTはGETに変換されてレスポンスを受け取る
- 成功判定はレスポンス本文で行い、JSONとして解釈でき、かつ `ok` が `true` の場合のみ成功とする（GASはスクリプトエラー時もステータス200でHTMLを返す場合があるため、ステータスコードでは判定しない）
- タイムアウトとリトライは1.2のとおり

### 6.2 送信項目

| 項目 | 形式 | 例 |
|---|---|---|
| プロジェクト名 | 文字列（4.1で正規化済み） | `ptt` |
| 開始日時 | `YYYY-MM-DD HH:mm:ss` | `2026-10-30 22:45:00` |
| 終了日時 | `YYYY-MM-DD HH:mm:ss` | `2026-10-30 23:58:12` |
| 作業時間 | 秒数（整数） | `4392` |

- スプレッドシート上では作業時間を `H:mm:ss` 形式（`[h]:mm:ss`）で表示する（3.2）
- 停止理由・フルパスは送信しない
- 日時は端末のローカルタイムで送信する
- 開始時刻・終了時刻は秒未満を切り捨ててから作業時間を計算する
- 日付で分割するため、1レコードの作業時間は最大24時間（`24:00:00`）となる

#### タイムゾーン

- 日付分割の境界判定と日時の文字列化は、端末のローカルタイムで行う
- GAS側のタイムゾーンは、セットアップ時の端末のタイムゾーンに合わせる（3.1）
- セットアップ後に端末のタイムゾーンを変更した場合はずれが生じるため、READMEに「タイムゾーンを変更した場合は `config.json` と `gas/` を削除して再セットアップする」旨を記載する

### 6.3 送信単位

- 1回の計測を1行（1レコード）として送信する
- 日付をまたいだ場合は、**翌日の `00:00:00` を境界として**日付ごとにレコードを分割する
- 分割は送信時にのみ行い、退避ファイルは分割しない

  例：`2026-10-30 23:00:00` 〜 `2026-10-31 01:30:00` の場合

  | プロジェクト名 | 開始日時 | 終了日時 | 作業時間 |
  |---|---|---|---|
  | ptt | 2026-10-30 23:00:00 | 2026-10-31 00:00:00 | 1:00:00 |
  | ptt | 2026-10-31 00:00:00 | 2026-10-31 01:30:00 | 1:30:00 |

  各行の作業時間の合計（2:30:00）は元の計測と一致する。

### 6.4 記録保護

- 計測中の記録は、プロセスごとに別の退避ファイルとして `~/.local/share/ptt/pending/` に保存する

#### ファイル名

- `<PID>-<開始時刻のエポックミリ秒>.json`（例：`12345-1793367900000.json`）
- PIDは再利用されるが、開始時刻（ミリ秒）との組み合わせで衝突しない

#### 内容

```json
{
  "project": "ptt",
  "start": "2026-10-30T22:45:00+09:00",
  "lastAlive": "2026-10-30T23:58:10+09:00"
}
```

- 日時はタイムゾーンオフセット付きの ISO 8601 形式

#### 書き込み

- 書き込みは、一時ファイル（`<ファイル名>.tmp`）に書いてからリネームするアトミック書き込みで行う（更新中に強制終了された場合の破損対策）
- 最終生存時刻は10秒ごとに更新する
- `SIGHUP` / `SIGINT` / `SIGTERM` 受信時は、表示より先にその時点の時刻を同期的に書き込んでから送信する（5.5）
- 強制終了・クラッシュ・電源断の場合は、最終生存時刻を終了時刻とする（失われる時間は最大10秒）
- 送信成功時に退避ファイルを削除する

### 6.5 再送

- 再送はセットアップ完了後（`config.json` が存在する状態）に行う。初回起動時は送信先が無いため、セットアップ完了後に実行する
- 再送はバックグラウンドで行い、計測の開始を待たせない
- `pending/` 内で、**最終生存時刻が60秒以上更新されていない `.json` ファイル**を、終了したプロセスの未送信分とみなして再送する
- 計測中の他ペインのファイル（10秒ごとに更新されている）は対象外になる
- 閾値60秒は更新間隔10秒の6倍であり、計測ループは時刻比較のみの軽い処理のため、負荷による更新遅延で誤って再送対象になる可能性は低い。なお、計測ループが60秒以上止まった場合はスリープとして停止処理に入るため、計測中のファイルの最終生存時刻が60秒以上古くなる状況は発生しない

### 6.6 二重送信の防止

スリープ復帰直後は、復帰したプロセス自身と、新しく起動した別ペインのプロセスが、同じ退避ファイルを同時に送信しようとする可能性がある。

- 送信する前に、退避ファイルをリネームする（例：`xxx.json` → `xxx.sending`）
- リネームに成功したプロセスだけが送信する
- リネームに失敗した（既にファイルがない）プロセスは何もしない
- どちらが送信しても、終了時刻は同じ（スリープ前の最終生存時刻）になる
- 送信に失敗した場合は `.sending` を `.json` に戻し、次回起動時の再送対象にする
- リネームは同一ディレクトリ内（同一ファイルシステム内）で行うため、原子的に実行される

#### 残った `.sending` の復旧

- 送信中にプロセスが落ちて `.sending` が残った場合に備え、起動時の再送処理で、更新日時が**2分以上前**の `.sending` を `.json` に戻してから再送対象に含める
- 2分は、送信の最大所要時間（10秒×3回＋試行間隔）より十分長い値

#### パーミッション（ファイル）

- GASのWebアプリのURLは書き込み権限そのものであるため、`config.json` は `0600`（本人のみ読み書き可）で作成する
- `~/.local/share/ptt/` と `pending/` は `0700` で作成する

#### 保存先

- 保存先は `~/.local/share/ptt` とする（CLIツールで一般的なXDG準拠のパスで、空白を含まずインストールコマンドが書きやすいため）
- `XDG_DATA_HOME` は参照しない

## 8. パーミッション

| パーミッション | 用途 |
|---|---|
| `--allow-net=script.google.com,script.googleusercontent.com` | GASへの送信・承認確認（リダイレクト先を含む） |
| `--allow-run=ioreg,clasp` | macOSの無操作時間の取得、初回セットアップでのclasp実行 |
| `--allow-env=HOME` | 保存先（ホームディレクトリ）の取得。それ以外の環境変数は参照しない |
| `--allow-read=$HOME/.local/share/ptt` | 設定・GAS・退避ファイルの読み込み |
| `--allow-write=$HOME/.local/share/ptt` | 設定・GAS・退避ファイルの書き込み |

- サブプロセスはDenoのサンドボックスの外で動作するため、`clasp` の実行を許可した時点で、pttの権限制限は実質的にclaspの権限まで広がる。初回セットアップの手作業をなくすためのトレードオフとしてREADMEに明記する
- `$HOME` はインストール時にシェルで展開され、絶対パスとして記録される。インストール時点で `~/.local/share/ptt` が存在しなくてもよい（pttが初回起動時に作成する）。親ディレクトリ（`~/.local/share`）が無い場合の `Deno.mkdir`（`recursive: true`）が許可範囲内で成功するかは、実装時に確認する
- パーミッションの正（source of truth）は本章とし、9章のインストール手順とREADMEは本章に合わせて更新する

## 9. インストール

インストール時に一度だけ実行する。以降は `ptt` で起動する。

```sh
# 前提：Node.js 22以上、clasp 3.x
npm install -g @google/clasp

# JSRからインストール（配布時）
deno install -g -n ptt \
  --allow-net=script.google.com,script.googleusercontent.com \
  --allow-run=ioreg,clasp \
  --allow-env=HOME \
  --allow-read="$HOME/.local/share/ptt" \
  --allow-write="$HOME/.local/share/ptt" \
  jsr:@h10hui/ptt

# ローカルのソースからインストール（開発時）
deno install -g -n ptt ...（同じフラグ）... main.ts

# PATHが通っていない場合（~/.zshrc）
export PATH="$HOME/.deno/bin:$PATH"

# パーミッション変更時は -f を付けて再インストール
deno install -g -f -n ptt ...（同じフラグ）... <対象>

# アンインストール
deno uninstall -g ptt
```

- ローカルの `main.ts` を指定した場合、コードの修正だけなら再インストールは不要
- パーミッションを変更した場合は再インストールが必要
